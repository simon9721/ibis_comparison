# Section 2 — Deliverables for tomorrow's meeting

Goal behind all of it: **get pybis (or a variant of it) as close to the HSPICE
transistor result as possible.** Each item says what we can show, where it lives,
and what is still missing.

## 1. Show the offset + time shift issue again

Two separate defects, both on io_buf stress cases (truncated pulses at
90/80/70/60/50% width):

- **The offset** — a settled-state Ku error, only on 90/60/50. Traced to
  `GUPCMD`: a capacitor across 1e15 ohm charged by a fixed packet per input edge,
  so a truncated pulse strands charge with no DC path to remove it. Not a true DC
  offset — a ~6 ns tail that looks permanent on a 10 ns plot.
- **The time shift ("defect B")** — falling 50% crossing **69-99 ps late** vs the
  transistor, on *every* case, where native IBIS is **5-26 ps early**.

**New this week**, and worth leading with — the full-swing decomposition:

| build | falling 50% vs transistor |
|---|---:|
| native IBIS | +34.6 ps |
| pybis InputDriven (stock) | +38.4 ps |
| pybis gate-state (ours) | +43.5 ps |

So on a clean edge **~80% of the distance to the transistor is the IBIS format
itself**, which native pays too. Our command layer costs ~5 ps. The problem is
specific to stress, where the gate-state-to-native gap goes from ~9 ps to
~75-125 ps.

Evidence: `results/archive/2026-09/defect_b_full_swing_2026-09-03/` (figure + FINDINGS),
`results/settled_offset_diagnosis_2026-08-27/`.

## 2. How delay_cmd reduces the offset — and the root cause we are still chasing

`delay_cmd` is **level-driven**: the command is a function of the current input
level, not of accumulated edge history, so it returns to exactly zero and strands
nothing. Result: the settled pad offset at reversal goes **63.9 mV -> 3.7 mV**
(transistor 7.5, native IBIS 6.4), and it improves all 29 matched stress cases
(108.6 -> 92.2 mV RMSE) — the only build beating native IBIS.

Evidence: `docs/delay_cmd_explained.md`, the offset-solved figure.

**The new part.** Defect B is now known to be **stress-specific** — the command
layer is fine on a clean edge (~9 ps from native) and only diverges once a pulse
is truncated. That is the *same* trigger as the offset. So the two defects,
always treated as unrelated, may be one mechanism: stranded `GUPCMD` charge
showing up once as a settled level and once as a delayed transition.

**If so, delay_cmd may already fix both — and nobody has checked.** Its
*amplitude* was measured; its *timing* never was. The experiment is cheap:
measure the falling-edge shift for delay_cmd vs edge-integrating gate-state on
the five stress cases. Shift collapses -> one mechanism, fix already exists.
Shift persists -> genuinely two defects. **This is the highest-value open item.**

Caveat to state honestly: delay_cmd has a known 1.25 ns dead zone after a
reversal where neither device is commanded on, which is why `predriver_cmd` was
previously preferred.

## 3. How adding R/L/C fixtures affects the extracted Ku/Kd

Re-solved Ku/Kd on altered fixtures against the shipped 50 ohm baseline. The
control reproduces the shipped solve to 2.4e-08, so the method is exact.

- In quiet regions Ku is **load-independent to four decimals** — the extraction
  is genuinely a device property, not a fixture artifact.
- A **resonant R+L+C fixture corrupts Ku** for 1.14 ns, reaching 0.26 of error.

Practical conclusion: added L and C are safe individually; the resonant
combination must be avoided when characterizing.

Evidence: `scripts/archive/test_kukd_fixture_variants.py` and its results
directory (script archived in the restructure; results kept).

## 4. Simulating pybis in HSPICE to remove the SPICE-engine variable

Every "native IBIS vs pybis" number changes **two** things at once — the IBIS
implementation *and* the SPICE engine (HSPICE vs ngspice). We built a translator
so the *same* pybis model runs in both, and the confound splits:

| | 50% crossing |
|---|---|
| pybis model in ngspice | 5.3371 ns |
| pybis model in HSPICE | 5.3375 ns |
| native IBIS in HSPICE | 5.3319 ns |

- **Engine** (same model, two simulators): **-0.5 ps rising, -0.0 ps falling**
- **Model** (same simulator, two implementations): **+5.6 ps**

**The engine is not the source** — provided ngspice is run converged. That proviso
is real: at a 1 ps step ngspice was an aliasing outlier that *doubled* the
apparent lag and inflated a whole validation sweep. Converged, the two engines
agree to half a picosecond.

Evidence: `scripts/pybis_subckt_to_hspice.py`,
`results/archive/2026-09/pybis_engine_model_decoupling_2026-09-03/`.

Worth mentioning: HSPICE cannot hold a 100+ point pwl inside a behavioural
expression, so the translator rewrites those as native `G ... PWL(1)` lookups.

## 5. The book (optional)

Leventhal & Green, *Semiconductor Modeling* (Springer 2006). Notes in
`docs/book_study_notes.md`. Three things it changed:

- **Golden waveforms** (12.9.6, 17.14) — replay a model's *own* V-T tables into
  the fixture that produced them. Self-contained: no transistor, no native IBIS,
  no engine confound. We had never done this. It is now the standing health
  check, and it settled the C_comp question.
- **Figure of Merit** (ch 16) — comparison **time-aligns first**, then scores.
  Our raw RMSE conflated timing with shape: 17.3 mV became 2.3 mV after a -9 ps
  shift. The "93 mV gap" was just 4.9 ps x an 18.5 mV/ps slew.
- **Appendix E** — canonical IBIS drives the wave from the V-T tables and uses
  I-V for reflections; pybis reconstructs from I-V x Ku(t). That architectural
  difference is the few-ps residual.

Honest note: I first misapplied 11.8.2's C_comp diagnostic and wrongly reported
that pybis over-applies C_comp. The golden-waveform test overturned it.

## 6. Suggested additions

**a. Lead with the error budget.** It reframes the whole goal. On a clean edge we
are ~5 ps from stock pybis and ~9 ps from native, while the format itself costs
~35 ps. **We are already near the format's floor on clean edges.** The distance
worth attacking is under stress, not on full swing.

**b. pybis reproduces all three buffers' own golden waveforms** — FOM 0.03-0.41%,
shift +4 to +8 ps (`results/golden_waveform_*_2026-09-03/`). Strong evidence the
core reconstruction is sound, and a good confidence slide.

**c. C_comp is handled correctly** — nominal beats zero on all 12 tables, and the
margin *scales with the die capacitance* (ex2 at 5 pF needs a -124 to -178 ps
correction without it). Worth showing because it closes a question that was open
all week, and because I had it backwards first.

**d. The 1.25 max|Ku| cap must be replaced.** It currently rejects ex2's own
control (base 1.283-1.343; shipped ex2 already 1.244). Healthy baselines differ
per silicon (inv_chain 1.03, ex2 1.28, io_buf 1.18), so no absolute number works.
It should become a within-buffer outlier test.

**e. max|Ku| is governed by C_comp x dV/dt against the device drive.** ex2
variants, all seven edge rates:

| variant | output edge | max\|Ku\| |
|---|---:|---:|
| `slowpre` (predriver halved) | 328 ps | 1.047 |
| `base` (control) | 200 ps | 1.283 |
| `nomiller` (Miller caps removed) | 208 ps | 1.299 |
| `skewp` (output PMOS halved) | 160 ps | 1.589 |
| `weak` (both output devices halved) | 152 ps | 1.779 |

Monotonic in the ratio: a slower edge shrinks the displacement current, a weaker
device shrinks the drive, and max|Ku| follows. For ex2 the displacement current
is 5 pF x 3.3 V / 200 ps = **82 mA against a ~51 mA drive** -- it *exceeds* the
device, so the two-fixture solve has to push Ku above 1 to balance. inv_chain,
with C_comp of 0.468 pF, sits at 1.03.

**I tested and rejected a wrong version of this first.** I proposed the cause was
gate-to-drain (Miller) feedthrough and built a `nomiller` variant with ex2's three
n4->out caps removed. It came back **identical to the control** (1.299 vs 1.283).
The caps are 20.5 fF against C_comp's 5 pF -- **0.41%**, 250x too small to matter,
which is arithmetic I should have done before proposing it. The null result is
useful anyway: it rules out the small capacitor and points at C_comp.

Consequence for the cap: a high max|Ku| is a *real signature of a large die
capacitance driven fast*, not a corrupted extraction. Capping it absolutely
rejects good models of exactly the buffers most worth modelling.

**f. Rules that cost us real time**, worth stating so they are not re-learned:
any bench for this model must **start with a real edge, never a held level** (it
initialises pulldown-on and latches state only on an edge); and **ngspice must be
converged** before any conclusion.
