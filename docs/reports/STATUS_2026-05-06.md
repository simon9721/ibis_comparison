This file captures the current technical status of the `IBIS_Comparison` project in as much detail as practical without copying full netlists.

## Project Goal

The goal is to compare native HSPICE IBIS simulation against a converted SPICE model running in ngspice, using the same `io_buf.ibs` source model and, as much as practical, comparable channel and stimulus setups.

There are now three important reference points in the project:

- native HSPICE IBIS
- SPISim's free-spice example files
- `pybis2spice`-generated ngspice decks

## Why The Full ngspice Run Is Slow

The full waveform-based PRBS/channel case is slow for expected reasons:

- SPISim's own waveform-based compact deck is already much slower than its ramp-based compact deck
- the full converted channel deck is `2 us`, while the SPISim compact decks are only `20 ns`
- the full deck contains many switching events instead of a single compact pulse
- each switching event activates the elapsed-time extraction machinery
- the channel deck also carries a 10-section RLGC ladder and nonlinear branch behavior

The key point is that the slowness is not evidence of a broken model. It is consistent with the kind of waveform-based free-spice approach SPISim itself describes.

## Alignment With SPISim

### Areas where alignment is strong

- elapsed-time extraction using scaled simulation time
- two short T-lines for edge/timing support
- separate rise/fall coefficient tables
- runtime hand-off logic between rise and fall behavior
- explicit branch assembly for device and clamp behavior
- compact validation bench concept
- ngspice plain batch/raw workflow

### Areas where alignment is still incomplete

- pybis2spice still uses its own coefficient-extraction path rather than SPISim's exact offline coefficient generation
- composite current and ISSO-style supply-current modeling are not implemented
- a full compact-bench numeric correlation study against native HSPICE has not yet been completed

## Practical Recommendations

Use these in order:

1. `SimIbis_FreeSpice_From_SPISim/Ibs2Spc_Coef.spc`
   Confirms the SPISim waveform reference deck runs on this machine.

2. `ngspice_pybis/tb_validation_pulse_ngspice_pybis_batch.sp`
   Best deck for compact converted-model validation.

3. `ngspice_pybis/tb_exp1_ngspice_pybis_inputdriven_100n_batch.sp`
   Best deck for quick PRBS/channel sanity checking.

4. `ngspice_pybis/tb_exp1_ngspice_pybis_inputdriven_batch.sp`
   Use only for long correlation runs.

## Current Bottom Line

- SPISim's ngspice examples are verified and usable as references.
- The converted `pybis2spice` input-driven model is structurally close to SPISim's waveform-based free-spice architecture.
- ngspice compatibility is working for compact benches and short channel runs.
- the remaining gap is now mostly runtime and full-correlation depth, not basic functionality.

## Suggested Next Technical Step

The next clean engineering step is to add automated measurements on the compact benches:

- propagation delay
- output peak
- undershoot/overshoot
- settling level
- edge slope or crossing times

That will make the comparison less qualitative and less dependent on raw-file inspection.
