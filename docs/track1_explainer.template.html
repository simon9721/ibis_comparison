One product, two factors, one probe

An IBIS file records Ku(t). A truncated pulse depends on the two things Ku(t) is made of. This is how you recover them from the file plus one pad measurement — and why each step of the recipe has to be where it is.

The argument, and the order of the page

1. IBIS gives you Ku(t), and Ku(t) is a product: map( gate(t) ).
2. A truncated pulse depends on the factors, not the product — the reversal asks where the gate was.
3. Ku(t) has shape at every instant — but it fixes only the composition. Pair any gate trajectory with the map that reproduces it and the full-swing waveform is identical, so the file cannot choose. A truncated pulse can: the chain then makes a different gate trajectory, and where it turns round depends on the gate's real speed.
4. But a few samples cannot pick a path out of infinitely many, so we need a physics prior on which gate paths this kind of circuit produces.
5. Prior + samples = the factorisation. The recipe is then just the three things that can corrupt it.

1 · the product

Ku(t) is a product, and the file pins only the product

The I-V tables and the V-T waveforms give Ku(t): the conducting fraction at every instant of one complete transition. That is the whole of what IBIS carries about the dynamics, and it is a composition of two things the file never separates — the gate's trajectory, and the curve that turns gate voltage into conducting fraction.

What the figure shows. Two models. Each row reads left to right as gate → map → Ku: the gate's path in time, the curve it is pushed through, and the Ku(t) that results. Row A has a slow gate and a map that turns on early; row B a fast, square gate and a map that turns on late. Follow the dashed line down each row — it marks one instant, the moment a truncated pulse would reverse.

This is not a hypothetical failure. The shipped model makes the row-B choice in its most extreme form — a command delay followed by a near-instant gate — so its gate is fully on or fully off at any reversal and never partway. That single choice is most of the 35–76 % it misses by.

3 · the frame

One thing to check before building on it

Everything above assumes Ku(t) can be written as map(gate(t)) — a fixed curve the gate is driven through. Worth confirming before the whole recipe rests on it, and it is a question a direct measurement can settle.

4 · the prior

What gate paths is this circuit able to produce?

Five samples cannot pick a trajectory out of the space of all trajectories. They can pick one out of a small family — if the family is right. So: what does the predriver actually do?

The physical picture. A CMOS inverter driving a large load is a current source while its input sits at the rail, because its conducting device is in saturation. Only near the destination rail does the device leave saturation and become a resistor. A constant current into a gate capacitance gives a ramp, which then tapers off at the end.

What the figure shows. That picture drawn as a circuit — a threshold element feeding a current source into a capacitance — with the four numbers it requires named underneath, and the output it produces plotted below, against the exponential an RC would give.

With the family fixed, the model is a chain of these stages driving the map. That is the whole architecture — nothing else is in it.

Of all the numbers in that architecture, one behaves quite differently from the rest: the number of stages. It is not a refinement, because a chain does not merely attenuate a short pulse.

And the file cannot pick it

What is being fitted here. A chain of stages, to the buffer's own full-swing Ku(t) — the curve from §1, the only thing the file contains. The question is whether that fit determines the chain.

How blind is the file once the stages are identical? Completely, over a range of a few stages. Three builds below, all fitted to the same file; the middle column is how well each reproduces it.

The rule that turns the band into candidates: the three smallest stage counts whose fit error is within 25 % of the best. That band contains the real netlist count on all 12 buffers, where taking the single best fit recovers it on 1 of 13 chains.

5 · the recipe

Three things can corrupt the factorisation, and the recipe is those three

C_comp corrupts the product before any factoring starts. K is one factor. The map shape is the other. Everything else is fitted to the file for free, and the one stressed run is spent choosing among the candidates those three produce.

First, repair the product

C_comp is not a model parameter. It is a number in the file that the file's own Ku tables were solved with, so a wrong value inflates the curve everything downstream is fitted to. It also happens to be the one thing the hysteresis plot from §3 can measure — which is worth seeing, because it explains both how the error was found and why track 1 has to settle for something weaker.

Three candidate stage counts times three candidate map shapes is nine models. The shapes are (vt_map, α) = (0.50, 0.70), (0.40, 0.60) and (0.40, 0.90), where the map is clip((g − vt_map)/(1 − vt_map), 0, 1)^α scaled between the file's own off and on levels. The single stressed run then does two jobs, and the order matters: it sets the amplitude first, then chooses.

Why the second job cannot use the obvious feature. The peak is the natural thing to compare, and it is precisely the thing the first job has just destroyed as evidence.

And why the samples must select rather than correct. One word covers three different physical situations, so no single fixed correction can serve them.

Three places this is not yet honest

1 · The shape grid was drawn from results on these same 12 buffers. Two of its three entries are the best of an earlier grid run on this set, so the selection has seen the answer key. A thirteenth buffer may need a shape the grid does not contain.

2 · x_lin is pinned at 0.45 on ten buffers and fitted on two. The pinned value is inside the 0.37–0.63 the real probed stages fitted, so it is defensible — but it should be one or the other.

3 · p is assumed. By the argument of §2 it is exactly the kind of parameter a partial-input observation can see and a full swing cannot, and the recipe already takes one such observation. An open gap rather than a closed one.
