# Clarity `.s2p` SPICE Model Walkthrough

This document uses one source Touchstone file:

```text
original_touchstone/Clarity_example.S2P
```

and compares two real converted ngspice-ready `.sp` models generated from that same source:

```text
vector_fit/vector_3r3c.sp
reduced_model/reduced_s2p_rx_delayeq_rc_ring.sp
```

Both files define the same subcircuit name and external ports:

```spice
s_equivalent p1 p2
```

That means either file can be used in the same two-port testbench:

```spice
.include 'vector_fit/vector_3r3c.sp'
Xchannel p1 p2 s_equivalent
Rterm p2 0 50
```

or:

```spice
.include 'reduced_model/reduced_s2p_rx_delayeq_rc_ring.sp'
Xchannel p1 p2 s_equivalent
Rterm p2 0 50
```

The external interface is the same, but the internal model philosophy is very different.

## 1. High-Level Difference

### Vector-Fit Model

The vector-fit model is generated by scikit-rf `VectorFitting`.

Flow:

```text
Touchstone .s2p
  -> scikit-rf Network
  -> scikit-rf VectorFitting
  -> scikit-rf write_spice_subcircuit_s
  -> vector_3r3c.sp
```

It tries to represent the full two-port S-matrix:

```text
S11, S12, S21, S22
```

It is a rational-function state-space style macromodel written as SPICE controlled sources, resistors, and capacitors.

### Reduced Model

The reduced model is custom code in this repo.

Flow:

```text
Touchstone .s2p
  -> scikit-rf Network only for parsing/data access
  -> extract RX through path, S21 in our bench convention
  -> custom delay + RC/tail/ringing fit
  -> custom SPICE writer
  -> reduced_s2p_rx_delayeq_rc_ring.sp
```

It does not try to preserve the full S-matrix. It focuses on matched 50 ohm RX-through transient behavior.

## 2. SPICE Syntax Primer

The two files use these SPICE primitives.

### Comments

```spice
* this is a comment
```

Lines beginning with `*` are comments.

### Subcircuit Definition

```spice
.SUBCKT s_equivalent p1 p2
...
.ENDS s_equivalent
```

or:

```spice
.subckt s_equivalent p1 p2
...
.ends s_equivalent
```

SPICE is generally case-insensitive for these directives. Both forms define a reusable block named `s_equivalent` with external nodes `p1` and `p2`.

### Resistor

```spice
R1 s1 0 50.0
```

Syntax:

```spice
Rname node1 node2 resistance
```

This places a resistor between `node1` and `node2`.

### Capacitor

```spice
Cx1_re_a1 x1_re_a1 0 1.0
```

Syntax:

```spice
Cname node1 node2 capacitance
```

In these generated models, capacitors often serve as state variables. They do not necessarily correspond to literal physical capacitors on a board.

### Independent Voltage Source

```spice
V1 p1 s1 0
```

Syntax:

```spice
Vname positive_node negative_node value
```

Here `V1` is a zero-volt source. It is not adding voltage. It is inserted so SPICE can sense current through that branch. Current-controlled sources like `F... V1 ...` need a voltage source name to reference.

### Voltage-Controlled Current Source

```spice
Gd1_1 0 s1 p1 0 0.00321404672153946
```

Syntax:

```spice
Gname output_plus output_minus control_plus control_minus transconductance
```

This source injects current between the output nodes. The current is proportional to the voltage between the control nodes.

### Current-Controlled Current Source

```spice
Fd1_1 0 s1 V1 0.160702336076973
```

Syntax:

```spice
Fname output_plus output_minus controlling_voltage_source gain
```

This source injects current proportional to the current through a named voltage source. Here the controlling source is `V1`.

### Voltage-Controlled Voltage Source

```spice
Ebrsrc1 brsrc1 0 ndelay 0 1
```

Syntax:

```spice
Ename output_plus output_minus control_plus control_minus gain
```

This source copies or scales a voltage. Here it creates an internal copy of the delayed input.

### Transmission Line Delay

```spice
Tdelay p1 0 ndelay 0 Z0=50 TD=0.36n
```

Syntax:

```spice
Tname in_plus in_minus out_plus out_minus Z0=value TD=delay
```

This is an ideal lossless transmission-line delay element. In the reduced model it explicitly inserts the fitted channel delay.

## 3. Vector-Fit Model Structure

File:

```text
vector_fit/vector_3r3c.sp
```

Header:

```spice
* EQUIVALENT CIRCUIT FOR VECTOR FITTED S-MATRIX
* Created using scikit-rf vectorFitting.py
*
.SUBCKT s_equivalent p1 p2
```

This tells us:

- The model came from scikit-rf vector fitting.
- It is intended to represent an S-matrix.
- The external ports are `p1` and `p2`.

Interpretation:

- The `_1_1` suffix means contribution associated with port 1 to port 1 behavior.
- The `_1_2` suffix means contribution associated with port 2 into the port 1 equation.

This block is not a simple physical network. It is a mathematical equivalent circuit for the fitted S-parameter relation.

## 4. Reduced Model Structure

File:

```text
reduced_model/reduced_s2p_rx_delayeq_rc_ring.sp
```

Header:

```spice
* Touchstone-only reduced S-parameter macromodel
* Scope: matched 50 ohm transient channel qualification, not arbitrary termination replacement.
.subckt s_equivalent p1 p2
```

This tells us:

- The model is custom, not scikit-rf vector-fit export.
- It is scoped to matched 50 ohm transient use.
- It is not intended to be an arbitrary termination/full S-matrix replacement.

### Explicit Delay

Actual contents:

```spice
Tdelay p1 0 ndelay 0 Z0=50 TD=0.36n
Rdelay_term ndelay 0 50
Rsum sum 0 1
```

Interpretation:

- `Tdelay` delays the signal from `p1` to internal node `ndelay`.
- `TD=0.36n` is the fitted bulk delay for this Clarity model.
- `Z0=50` matches the intended 50 ohm channel bench.
- `Rdelay_term ndelay 0 50` terminates the delayed line.
- `Rsum sum 0 1` creates a summing node where controlled current sources can accumulate the fitted response.

The vector-fit model hides delay inside poles and phase. The reduced model makes delay explicit.

### RC Basis Branches

Actual contents:

```spice
Ebrsrc1 brsrc1 0 ndelay 0 1
Rbr1 brsrc1 br1 1000
Cbr1 br1 0 3e-14
Gsum1 0 sum br1 0 0.880899573043
Ebrsrc2 brsrc2 0 ndelay 0 1
Rbr2 brsrc2 br2 1000
Cbr2 br2 0 8e-14
Gsum2 0 sum br2 0 1.02366690358
Ebrsrc3 brsrc3 0 ndelay 0 1
Rbr3 brsrc3 br3 1000
Cbr3 br3 0 2e-13
Gsum3 0 sum br3 0 -0.120764584052
Ebrsrc4 brsrc4 0 ndelay 0 1
Rbr4 brsrc4 br4 1000
Cbr4 br4 0 7e-13
Gsum4 0 sum br4 0 -0.0687396987908
Ebrsrc5 brsrc5 0 ndelay 0 1
Rbr5 brsrc5 br5 1000
Cbr5 br5 0 2.5e-12
Gsum5 0 sum br5 0 -0.691991110033
Ebrsrc6 brsrc6 0 ndelay 0 1
Rbr6 brsrc6 br6 1000
Cbr6 br6 0 8e-12
Gsum6 0 sum br6 0 0.0241158192395
```

Each RC branch has the same pattern:

```spice
EbrsrcN brsrcN 0 ndelay 0 1
RbrN brsrcN brN 1000
CbrN brN 0 <capacitance>
GsumN 0 sum brN 0 <gain>
```

Interpretation:

- `EbrsrcN` copies the delayed input into a branch.
- `RbrN` and `CbrN` create a first-order low-pass response.
- The time constant is approximately `R * C`.
- Since `R = 1000 ohm`, the branch time constants are:
  - `3e-14 F * 1000 = 3e-11 s = 0.03 ns`
  - `8e-14 F * 1000 = 8e-11 s = 0.08 ns`
  - `2e-13 F * 1000 = 2e-10 s = 0.2 ns`
  - `7e-13 F * 1000 = 7e-10 s = 0.7 ns`
  - `2.5e-12 F * 1000 = 2.5e-9 s = 2.5 ns`
  - `8e-12 F * 1000 = 8e-9 s = 8 ns`
- `GsumN` injects each branch contribution into the summing node.
- Positive and negative gains combine to approximate the through-path response.

This block is much easier to reason about than the vector-fit state network: it is explicitly a weighted sum of low-pass responses.

### Tail Branches

Actual contents:

```spice
Etailfsrc1 tailfsrc1 0 ndelay 0 1
Rtailf1 tailfsrc1 tailf1 1000
Ctailf1 tailf1 0 5e-14
Gtailf1 0 sum tailf1 0 -0.664651855307
Etailssrc1 tailssrc1 0 ndelay 0 1
Rtails1 tailssrc1 tails1 1000
Ctails1 tails1 0 2e-12
Gtails1 0 sum tails1 0 0.664651855307
Etailfsrc2 tailfsrc2 0 ndelay 0 1
Rtailf2 tailfsrc2 tailf2 1000
Ctailf2 tailf2 0 2e-13
Gtailf2 0 sum tailf2 0 -0.144880403286
Etailssrc2 tailssrc2 0 ndelay 0 1
Rtails2 tailssrc2 tails2 1000
Ctails2 tails2 0 8e-12
Gtails2 0 sum tails2 0 0.144880403286
```

Interpretation:

- Tail branches are paired fast and slow low-pass responses.
- The gains are equal and opposite.
- That creates a response shaped like:

```text
lowpass_fast - lowpass_slow
```

or the opposite sign, depending on fitted gain.

This helps model settling tails without changing the final DC level too aggressively.

### Ringing / Feedthrough Basis

Actual contents for the first ringing group:

```spice
Eringbase1 ringbase1 0 p1 0 1
Eringfsrc1 ringfsrc1 0 ringbase1 0 1
Rringf1 ringfsrc1 ringf1 1000
Cringf1 ringf1 0 5e-15
Gringf1 0 sum ringf1 0 -0.385007390796
Eringssrc1 ringssrc1 0 ringbase1 0 1
Rrings1 ringssrc1 rings1 1000
Crings1 rings1 0 3e-14
Grings1 0 sum rings1 0 0.385007390796
```

Actual contents for a delayed ringing group:

```spice
Tringdelay4 p1 0 ringbase4 0 Z0=1e12 TD=0.04n
Rringdelay_term4 ringbase4 0 1e12
Eringfsrc4 ringfsrc4 0 ringbase4 0 1
Rringf4 ringfsrc4 ringf4 1000
Cringf4 ringf4 0 5e-15
Gringf4 0 sum ringf4 0 -0.376690953922
Eringssrc4 ringssrc4 0 ringbase4 0 1
Rrings4 ringssrc4 rings4 1000
Crings4 rings4 0 3e-14
Grings4 0 sum rings4 0 0.376690953922
```

Interpretation:

- Ringing groups are zero-DC pulse-shaping terms.
- They use a fast branch and a slower branch with opposite signs.
- That creates a short transient bump or dip without permanently changing the DC output level.
- Some groups use `Eringbase... p1` directly, which means no extra ring delay.
- Other groups use `Tringdelay... TD=...`, which delays that ringing feature.
- `Z0=1e12` makes the ring delay line behave like a near-ideal voltage delay with minimal loading.

The reduced model includes ringing delays:

```text
0 ns
0.04 ns
0.08 ns
0.14 ns
0.22 ns
```

and each delay has several fast/slow RC shape options.

This is specifically aimed at fast-edge behavior. That is one reason the reduced model is more targeted than full vector fitting.

### Output Driver

Actual contents:

```spice
Eout outdrv 0 sum 0 2
Rout outdrv p2 50
.ends s_equivalent
```

Interpretation:

- `Eout` converts the internal summing-node voltage into an output drive.
- The gain is `2`.
- `Rout outdrv p2 50` gives the reduced model a 50 ohm output resistance into external port `p2`.

The factor of `2` is part of the matched-source/load scaling used by this reduced modeling approach. The reduced fitting uses an incident-wave-style 0.5 source scaling internally, so the output stage restores the port voltage scaling for the bench.

## 5. Direct Side-by-Side Comparison

### External Interface

Both:

```spice
s_equivalent p1 p2
```

Vector-fit:

```spice
.SUBCKT s_equivalent p1 p2
...
.ENDS s_equivalent
```

Reduced:

```spice
.subckt s_equivalent p1 p2
...
.ends s_equivalent
```

### Modeling Goal

Vector-fit:

```text
Represent full S11/S12/S21/S22 two-port behavior.
```

Reduced:

```text
Represent matched 50 ohm RX-through transient behavior.
```

### Internal Structure

Vector-fit:

```text
50 ohm reference port networks
+ current/voltage sensing sources
+ rational-function pole states
+ controlled-source coupling terms
```

Reduced:

```text
explicit delay
+ weighted RC low-pass basis
+ tail basis
+ ringing/feedthrough basis
+ 50 ohm output stage
```

### Readability

Vector-fit:

- More general.
- Harder to read directly.
- Coefficients are rational-fit residues and pole-state couplings.

Reduced:

- Less general.
- Easier to explain.
- Coefficients are weighted transient basis gains.

### Trust Scope

Vector-fit:

- Candidate for general two-port replacement.
- Must pass passivity, dense singular value, frequency fit, and transient smoke gates.

Reduced:

- Candidate for matched 50 ohm RX-through transient use.
- Should not be advertised as arbitrary termination or full S-matrix replacement.

## 6. Demo Talking Points

For a presentation, the simplest explanation is:

1. Both files plug into ngspice with the same `Xchannel p1 p2 s_equivalent`.
2. The vector-fit file is a full mathematical S-matrix macromodel.
3. The reduced file is a targeted transient-response model.
4. The vector-fit model is more general but harder to stabilize and validate.
5. The reduced model is less general but easier to make match the RX waveform under fixed 50 ohm conditions.
6. This is why our report separates `RX_READY`, `REFLECTION_READY`, and `FULL_MODEL_READY`.
