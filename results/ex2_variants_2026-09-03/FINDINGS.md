# ex2 open-drain: the structural test the study had been missing

Item 2 of `0902_plan.md`. Every buffer in the study is push-pull. The gate-state
model, the command layer and the pybis subcircuit were all built around a pullup
and a pulldown. An open-drain buffer has neither symmetry — it can only pull the
pad **low**, and reaches high through an external termination. It is the one
device that tests whether the machinery quietly assumed push-pull.

ex2 is a real layout-extracted netlist, so it does not admit width or stage
sweeps. It admits exactly this one change: strip the output pullup.

`scripts/make_ex2_opendrain_variant.py` removes the five output-stage pullup
PMOS (mx24–28), leaving the three-stage predriver, the five pulldown NMOS
(mx15–19) and the Miller caps untouched. The result is a correct open-drain
netlist: only NMOS and the n4→out caps touch the pad.

## What generalized, and what did not

**The structure generalized.** s2ibispy typed it `Open_drain` and produced a
`[Pulldown]` table with no `[Pullup]` — exactly right. The netlist edit, the
recipe retyping, and the model topology all work.

**The characterization did not.** Two assumptions surfaced, one fixable and one
not, both from the buffer being push-pull nowhere.

### 1. The fixtures assumed push-pull (fixed)

The inherited recipe characterizes with two fixtures, 50 Ω to 0 V and 50 Ω to
VCC. An open-drain pad cannot rise into a fixture that pulls it to ground, so the
rising-into-0 V waveform is flat at 0 and ibischk rejects it:

```
[Rising Waveform] with V_fixture=0V has DC endpoints of 0.00V and -0.00V
```

An open-drain is characterized against the pull-up fixture alone. The generator
now keeps only the 50 Ω-to-VCC fixture for its waveforms. This cleared six of
the twelve errors.

### 2. The ground clamp double-counts the pulldown (fixed — see update below)

The remaining six errors are a DC inconsistency: the waveform tables settle to
1.34 V and 3.30 V, but the same load applied to the I-V tables yields 0.75 V and
1.34 V — a 100–330% mismatch. The cause is a spurious `[GND Clamp]`.

A real ground clamp is an ESD diode: it conducts only for **pad below 0 V**. This
model's clamp instead rises with positive pad voltage, tracking the pulldown
exactly:

| pad voltage | `[Pulldown]` | `[GND Clamp]` |
|---:|---:|---:|
| 0 V | 0 mA | — |
| +2.83 V | — | 50.7 mA |
| +3.3 V | 51.0 mA | ~51 mA |

The NMOS pulldown current is being counted **twice** — once correctly in
`[Pulldown]`, once again in `[GND Clamp]`. ibischk sums them, so a 50 Ω-to-VCC
load lands the off-state pad at `(3.3 − 0.75)/50 ≈ 51 mA → 0.75 V` instead of the
3.30 V the waveform recorded.

**Root cause.** s2ibispy extracts the ground clamp by holding the input in the
state that turns the *driver* off, then sweeping the pad. For a push-pull buffer
that state cleanly isolates the ESD clamps from both drivers. This open-drain has
no enable — `in` is its only control — so there is no input state that turns the
sole driver off while a separate clamp remains. The clamp sweep captures the NMOS
conduction and files it as `[GND Clamp]`, and the pulldown is double-counted.

This is a genuine open-drain limitation in s2ibispy's clamp extraction, exposed
by the structural test. It is not the flat 10-line kind of fix the SPICE timeout
was; it needs the clamp-characterization state to be correct for an enable-less
single-driver output, which is a real change to the extraction logic.

## Where this left item 2 (before the fix)

The open-drain netlist and the generator are done and correct. The finding is
that **the study's conversion pipeline does not yet produce a valid open-drain
model**, for a specific and identified reason, and closing that is an upstream
s2ibispy task rather than a recipe tweak.

Two ways forward, for a decision:

- **Fix the clamp extraction upstream** so an enable-less open-drain is
  characterized with its single driver held off and no clamp double-count. This
  is the correct fix and unblocks open-drain generally.
- **Add an enable to the ex2 open-drain** so it has a real high-Z state, matching
  how open-drain parts are usually built and characterized. This sidesteps the
  extraction bug but changes the device.

Until one is done, the transistor-vs-native-vs-pybis comparison that item 2 is
ultimately for cannot run on open-drain: there is no valid IBIS model to compare
against.

## Update 2026-09-03: fixed upstream, and the comparison run

The clamp double-count is **fixed** in s2ibispy (commit `c780715`): for an
enable-less open-drain the clamp curves now drive the input to the driver-off
level instead of a weak tie to ground, so the sweep sees the ESD clamps alone.
`[GND Clamp]` at +3.3 V dropped from 51 mA to 0.8 nA and the model passes
ibischk with zero errors. The push-pull inv_chain and ex2 models re-convert
bit-identical, so nothing else moved.

With a valid model, the comparison item 2 exists for ran — transistor vs native
IBIS vs pybis, on a pull-up load (50 Ω to VCC, 2 pF), which is how open-drain
nets are actually built. Full swing.

| build | RMSE | worst | release edge | drive edge |
|---|---:|---:|---:|---:|
| native IBIS | 35.8 mV | 255 mV | −37 ps | −35 ps |
| pybis | 130.4 mV | 830 mV | +144 ps | +160 ps |

**Both track the open-drain.** native IBIS sits close to the transistor and
slightly leads it. pybis follows the shape correctly on both edges but lags
~150 ps and slews slower, which is where its 830 mV worst-case lives.

This is the **same pattern as the push-pull inv_chain variants, more
pronounced**: pybis is a constant multiple of native IBIS (here 3.6×, against
2.8–3.4× push-pull) and pybis runs late where native IBIS does not (here ~150 ps,
against 7–9 ps push-pull). The larger numbers are the harder edge — an open-drain
release through a 50 Ω pull-up is a slower, softer transition than a push-pull
drive, and pybis's command/gate timing lags more on it.

So the gate-state/pybis machinery **does generalize to a buffer with no pullup**,
once the characterization is correct. It is not accurate to native-IBIS levels
on open-drain, but it fails in the same direction and by the same mechanism it
does on push-pull, not in a new way. That is the useful conclusion: open-drain
did not expose a hidden push-pull assumption in the *model* — only in the
*characterization*, which is now fixed.

One bench note, from a bug found and fixed while running this: the InputDriven
model initializes with the pulldown on (output low) and establishes state only
on the first detected edge, so the stimulus must start in the low state or t < 0
is compared against the wrong initial condition. The push-pull benches happened
to start low; this one had to be made to.
