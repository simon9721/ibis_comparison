# inv_chain s2ibispy Slow/Fast Conversion

## Status

Both requested SPICE-to-IBIS conversions completed with the local s2ibispy package:

- Slow input: `tr = tf = 1 ns`
- Fast input: `tr = tf = 5 ps`

Both final IBIS files pass `ibischk7` with zero errors. Each has three noncritical warnings: `Vinl` and `Vinh` are emitted for an Output model, and the Vmeas timing-test load parameters are omitted.

## Generated Models

- `slow_1ns/inv_chain_slow_1ns.ibs`
- `fast_5ps/inv_chain_fast_5ps.ibs`

Both models use:

- component `invchain`
- output model `driver2`
- 1.8 V typical, 1.7 V minimum, and 1.9 V maximum supply
- 27 C for all three corners
- `C_comp = 0.468 pF`
- two rising and two falling waveform fixtures: 50 ohm to 1.8 V and 50 ohm to 0 V
- 6 ns characterization capture with 1000 waveform points
- identical typical/slow/fast transistor corner files

The snapshotted source netlists and model library are under `inputs/`. The exact recipes are under `configs/`. The only characterization difference between the two recipes is `tr/tf`.

## Reproduction

From the repository root:

```powershell
$env:PYTHONPATH = (Resolve-Path ..\s2ibispy\src).Path
$env:PATH = "C:\synopsys\Hspice_T-2022.06\WIN64;$env:PATH"
$study = (Resolve-Path results\inv_chain_s2ibispy_slow_fast_2026-07-27).Path

Push-Location "$study\inputs"
try {
  py -3.14 -m s2ibispy `
    "$study\configs\inv_chain_slow_1ns.yaml" `
    --outdir "$study\slow_1ns" `
    --spice-type hspice --iterate 0 --cleanup 0 `
    --ibischk C:\Users\sh3qm\code\s2ibispy\resources\ibischk\ibischk7.exe

  py -3.14 -m s2ibispy `
    "$study\configs\inv_chain_fast_5ps.yaml" `
    --outdir "$study\fast_5ps" `
    --spice-type hspice --iterate 0 --cleanup 0 `
    --ibischk C:\Users\sh3qm\code\s2ibispy\resources\ibischk\ibischk7.exe
}
finally {
  Pop-Location
}
```

The `Push-Location` makes `HL18G-S3.7S.lib` visible to HSPICE. If the first HSPICE process times out only during license startup, repeat the same command with `--iterate 1` after its output files appear.

## Validation

| Model | ibischk7 | HSPICE native-IBIS load | Pad RMSE vs cached transistor | Rise 50% | Fall 50% |
|---|---:|---:|---:|---:|---:|
| Slow 1 ns | 0 errors, 3 warnings | completed | 379.48 mV | 5.9329 ns | 15.9039 ns |
| Fast 5 ps | 0 errors, 3 warnings | completed | 12.94 mV | 5.3378 ns | 15.3075 ns |
| Transistor reference | n/a | cached, not rerun | 0 mV | 5.3324 ns | 15.2981 ns |

Sanity bench:

- HSPICE native IBIS instance
- 1.8 V supply
- 1 ps input edges at 5 ns and 15 ns
- direct `50 ohm || 2 pF` load
- no package parasitics and no channel

The fast-generated IBIS is close to the transistor reference in this normal-edge bench. The slow-generated IBIS preserves almost the same output slew after the inverter chain regenerates the input, but its switching event is about 0.60 ns later. This is the expected consequence of characterizing the same transistor buffer with a 1 ns input edge.

HSPICE reports two runtime warnings for each model because the generated ISSO PU/PD currents are not exactly zero at Vcc. Both jobs still conclude normally and produce `.tr0` data.

## Cold-Start Note

The first fast conversion attempt hit s2ibispy's fixed 60-second per-job timeout while HSPICE was performing a cold license startup. HSPICE completed the DC output afterward, but s2ibispy had already built an invalid intermediate IBIS with a missing typical pullup table.

The final model was rebuilt with `--iterate 1`, which parsed the completed HSPICE outputs. The final `fast_5ps/inv_chain_fast_5ps.ibs` is the repaired file and passes `ibischk7`; the failed attempt remains visible in `fast_5ps/conversion.err.log` as useful process evidence.
