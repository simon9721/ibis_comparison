OLD Approach (Mixed NI+N2):
  ──────────────────────────
  Step 1: Edge detected (N2 becomes positive) ✓
  Step 2: NI starts converging but oscillates ±0.05V during iterations
  Step 3: Old_Selector = 0.5 + 0.5×tanh(200×(0.5×NI_osc + 0.5×N2))
          When NI = +0.05: selector = 0.5 + 0.5×tanh(200×0.035) ≈ 0.62 → FAST
          When NI = -0.05: selector = 0.5 + 0.5×tanh(200×0.045) ≈ 0.58 → FAST/SLOW boundary
  Step 4: Selector oscillates: 0.52 → 0.62 → 0.53 → 0.61...
  Step 5: Family assignment flips back-and-forth
  
  Solver behavior:
    Iteration 1: Ku_rise selected → calculates output with fast family
    Iteration 2: Ku_fall selected (oops!) → recalculates with slow family
    Iteration 3: Back to Ku_rise → recalculates again
    ...
    This flip-flopping causes:
      • Output discontinuities
      • Jacobian matrix re-evaluation
      • Newton step rejection
      • Timestep reduced by solver
      • Extra iterations required
  
  Result: ~18 Newton iterations needed, 1.2 ns solver time


NEW Approach (Pure N2):
  ─────────────────────
  Step 1: Edge detected (N2 becomes positive) ✓
  Step 2: NI starts converging but oscillates ±0.05V during iterations
  Step 3: New_Selector = 0.5 + 0.5×tanh(200×N2)
          N2 ≈ +1.2V (stable, even if NI wobbles)
          Selector ≈ 0.95 (LOCKED on fast family) ✓
  Step 4: Selector stays at 0.95 (never crosses family threshold)
  Step 5: Family assignment LOCKED: Ku_rise for all iterations
  
  Solver behavior:
    Iteration 1: Ku_rise selected → calculates output with fast family
    Iteration 2: Ku_rise still selected (good!) → refines calculation
    Iteration 3: Ku_rise still selected → further refinement
    ...
    This consistency:
      • Output behavior is smooth
      • Jacobian matrix stable
      • Newton steps accepted
      • Timestep can grow
      • Convergence achieved quickly
  
  Result: ~8 Newton iterations needed, 0.3 ns solver time

================================================================================
WHY THIS MATTERS PHYSICALLY
================================================================================

Fundamental Problem (OLD):
  ──────────────────────────
  When NI oscillates (inherent to numerical methods), mixing it with the
  selector causes the family decision to "hunt." The solver then:
    1. Commits to one family
    2. NI oscillates differently
    3. Selector changes
    4. Family switches
    5. Output derivatives change
    6. Solver recalculates
    7. Back to step 1...
  
  This is a feedback loop that destabilizes convergence.

Elegant Solution (NEW):
  ────────────────────
  Use ONLY the polarity signal (N2), which is the TIME DERIVATIVE of NI.
  Because differentiation removes DC and slow drifts, N2 is inherently
  more stable than NI, even during convergence hunting. The selector
  commits once and locks in, allowing clean Newton iteration.
  
  Physical analogy:
    • OLD = "listen to the noisy position measurement"
    • NEW = "listen to the clean velocity direction"
  
  Velocity (sign of slope) is more stable than position (oscillates).
